# Opening the upstream pull request

A pull request (PR) asks the Homarr maintainers to merge one branch of your fork,
`feat/drop-url-to-add-app`, into their `dev` branch. Only that branch's commits are part of it;
nothing else in your fork is involved. Most of this is automated by
[`scripts/open-upstream-pr.sh`](../scripts/open-upstream-pr.sh).

## Why it starts as a draft

The feature builds on someone else's open PR, [#6562](https://github.com/homarr-labs/homarr/pull/6562).
That PR adds the guarded website fetcher, and the maintainers are holding it for a network
security review. Until #6562 is merged, your PR has to include its 15 commits so it builds. A
**draft** PR is the normal way to say "ready to look at, but waiting on something": it's visible
and can be discussed, but it can't be merged by accident. The PR description says this up front
and tells reviewers that only the last two commits are yours.

## Steps

### 1. One-time setup

Complete steps 1 and 2 of [First-time setup](staying-current.md#first-time-setup): rebuild the
dev container so `gh` is available, then run `gh auth login`.

### 2. Record a short demo (recommended)

A 5 to 10 second GIF of dragging a URL onto a board and the tile appearing is what reviewers look
at first. On Windows, [ScreenToGif](https://www.screentogif.com/) works well. Keep it under 10 MB.
You'll add it in step 6.

### 3. Fill in the description

Open [`docs/pr-body.md`](pr-body.md) on the `fork` branch and replace the
`<!-- BROWSERS YOU TESTED -->` placeholder with the browsers you actually tried. Commit and push it
([Editing the fork branch](staying-current.md#editing-the-fork-branch)), or edit it directly on
GitHub. Read the rest too: it goes out under your name.

### 4. Final checks

In the homarr checkout, on the feature branch:

```sh
git switch feat/drop-url-to-add-app
bun run typecheck && bun run lint && bun run test
```

All three must pass. The PR template asks you to confirm they do.

### 5. Open the PR

```sh
bash <(git show origin/fork:scripts/open-upstream-pr.sh)
```

The script shows the branch, title and commit count, and asks before doing anything. It then
pushes the branch and opens the draft PR on `homarr-labs/homarr`, printing its URL.

> **GitHub MCP instead of the script:** the branch has to be pushed first
> (`git push -u origin feat/drop-url-to-add-app`). Then ask Copilot Chat in agent mode:
> *"Create a draft pull request in homarr-labs/homarr from mawcs:feat/drop-url-to-add-app into dev.
> Use the title "feat(board): add apps by dropping a URL onto the board in edit mode" and the contents of docs/pr-body.md from the fork
> branch as the description."*

### 6. Add the demo and tell #6562's author

1. Open the PR URL, click **⋯ → Edit** on the description, and drag your GIF onto the
   `<!-- demo GIF here -->` line. GitHub uploads it. Save.
2. Leave a short comment on #6562 so its author knows that something depends on their work.
   Replace `NNNN` with your PR number:

   ```sh
   gh pr comment 6562 --repo homarr-labs/homarr --body "Hi @junkerderprovinz, I've built a small feature on top of this PR in #NNNN: dropping a URL onto a board in edit mode creates an app from the page's title and icon. It adds \`fetchWebsiteMetadataAsync\` next to your \`fetchFaviconUrlAsync\`, which reads the \`<title>\` from the same guarded request, so it inherits your checks. Mine stays a draft until this one is merged. If you'd rather the title extraction lived here, or should work differently, I'm happy to adjust."
   ```

That's the PR submitted, which is this fork's definition of done. Update the project record in
your Command Center (`projects/homarr-drag-and-drop.md`).

## What to expect afterwards

- **Bots arrive within minutes.** *CodeRabbit* posts an automated review, and some of its
  comments may be wrong. Fix what's right, and reply briefly where you disagree. A *Dokploy*
  message saying the preview deployment was blocked is normal for outside contributors. A
  *semantic PR* check validates the title format; yours already follows it.
- **CI won't start by itself.** For first-time contributors, a maintainer has to approve the
  checks before they run.
- **Reviews take a while.** Days or weeks is normal, especially while #6562 is waiting. Maintainers
  sometimes post reviews marked *"generated by AI during triage"*; treat them like any review.
- **Making changes:** commit to the feature branch and `git push`. The PR updates itself. Ask
  Claude for help with review comments: paste the comment and say which PR.
- **"Is a bot writing this?"** It has been asked on #6562. The description already says you
  used Claude Code; answer the same way if asked.

## When #6562 is merged

```sh
bash <(git show origin/fork:scripts/update-feature-branch.sh)    # drops the #6562 copies
bun run typecheck && bun run lint && bun run test
git push --force-with-lease origin feat/drop-url-to-add-app
```

Then remove the *Depends on #6562* note from the description and mark the PR ready:
`gh pr ready <number> --repo homarr-labs/homarr`.

## Useful commands

| What | Command |
|---|---|
| See your PR, its checks and comments | `gh pr view <number> --repo homarr-labs/homarr --comments` |
| Open it in the browser | `gh pr view <number> --repo homarr-labs/homarr --web` |
| Status of the PR's checks | `gh pr checks <number> --repo homarr-labs/homarr` |
| Is #6562 merged yet? | `gh pr view 6562 --repo homarr-labs/homarr --json state --jq .state` |
